# v1.1.1 stability candidate

Based on main `e0998f5`. PR #3 commits `46d6059` and `a4eaa82` are cherry-picked with chyinan's authorship preserved. No CI changes, external merge, push, release or tag.

## Issue #2: diagnosis remains unconfirmed

The reported Windows 11 build 26300.9711 setup has two 2560×1440 monitors at X=0 and X=2560; DPI was not supplied. Its freeze has **not** been reproduced here. Do not close Issue #2 on the strength of this candidate.

Confirmed code defects addressed:

- Placement transformed absolute desktop pixels using the newly created dialog's DPI, then assigned WPF coordinates. This is not a valid conversion across monitors with different DPI/origins. Placement now uses native physical bounds after rendering, and clamps after display/work-area/DPI messages. Negative origins are preserved. Minimized owners are restored.
- Browser sign-in bypassed Settings/ProfileManager ownership and placement. It now uses the active auxiliary owner, has a taskbar entry, and detaches before active-account reauthorization closes Codex. Modal name prompts block reentrant Add profile requests.
- Login cleanup waited without a deadline for process exit and stdout/stderr EOF. A subprocess fixture confirms that a child can retain those pipes after its parent exits. Reads now cancel independently; process termination has a five-second deadline. This is a login reliability defect, **not evidence that it caused Issue #2**.

No account storage, switch transaction or rollback redesign. CLI availability is checked before showing login progress; known startup, nonzero exit, missing authorization, timeout, permission and cleanup failures have safe EN/RU/ZH messages. CLI output is discarded, not parsed or logged. Existing staging/commit boundaries remain intact.
