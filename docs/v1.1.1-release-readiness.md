## Подтверждённые исправленные регрессии

- Исправлены две привязки WPF smoke-стенда. Фикстуры Settings и удаления не передавали новый async-делегат проверки лимитов. Фикстура удаления также обращалась к прежнему синхронному имени метода. Smoke теперь вызывает `RemoveProfileAsync` и проверяет завершение задачи в сценарии без фонового writer.
- Подтверждённых регрессий в коде приложения при этом прогоне не выявлено.

## Непроверенные сценарии с реальными аккаунтами

- Браузерный вход и повторная авторизация. Capture и переключение реальных Desktop-сессий, запуск Codex после переключения и rollback после реального сбоя запуска.
- Сохранность живой истории и профилей, обновление реальных лимитов и проверка логов при этих операциях.

### Штатное обновление v1.1.0 → v1.1.1

9 ноября 2026 года, исходный HEAD `f971d0a`. Результат **NOT TESTED**. Изоляция для прогона не использовалась: на Windows 22H2 компоненты `Containers-DisposableClientVM` и `Microsoft-Hyper-V-All` отключены, активного гипервизора и доступной Windows VM не обнаружено. Штатные установщики в основной Windows не запускались.

Скачан опубликованный файл `CodexSwapAccount-win-x64-setup.exe` (GitHub asset ID `633670796`, 69 549 445 байт, ProductVersion `1.1.0`). SHA-256 `9567c1348e0cb577fd7317a4feadce3fb322e5a29a73b2fddaf6df26adeafa45` совпал с digest GitHub API и строкой из опубликованного `SHA256SUMS.txt`. У обоих установщиков штатный `AppId=CodexSwapAccount`. [Релиз v1.1.0](https://github.com/ZOONGG/codex-swap-account/releases/tag/v1.1.0)

#### Повторяемый прогон в Windows Sandbox

1. Открыть `artifacts/upgrade-acceptance/ReleaseUpgrade.wsb` на хосте с Windows Sandbox. Конфигурация отключает сеть и монтирует каталог с установщиками и `installer/Test-ReleaseUpgrade.ps1` только для чтения. При переносе комплекта указать абсолютный путь к каталогу в `HostFolder`.
2. Сценарий сверяет SHA-256, устанавливает v1.1.0 и создаёт два фиктивных профиля, синтетический общий `auth.json`, историю `history.jsonl`, метаданные профилей, отметку активного профиля, файл-маркер в каталоге резервных копий и настройки. Подтвердить контрольный запуск в трее, окнах WPF и штатный выход. Сохранность этих данных пока не проверена.
3. Сценарий запускает v1.1.1 с аргументами встроенного обновления `/UPDATE=1 /SILENT /NORESTART`. Он проверяет версию EXE и запись удаления, ожидает автоматического запуска, затем повторяет проверку при ручном запуске. На каждом запуске оператор проверяет интерфейс, настройки, активный профиль и отсутствие предупреждений миграции. Удаление запускается через зарегистрированный деинсталлятор. Хеши тестовых файлов и выбранные поля настроек сравниваются до обновления, после обоих запусков и после удаления.
4. Сохранить журналы и снимки из `%TEMP%\CodexSwapAccount-upgrade-acceptance` до закрытия песочницы. Сценарий проверен синтаксически и отклоняет запуск под обычным пользователем хоста. В гостевой Windows он ещё не выполнялся.

Прогон покрывает локальный запуск установщика с параметрами обновления и синтетические данные. Отдельными ограничениями остаются реальный вход, Chromium, сетевой маршрут загрузки обновления и миграция резервной копии, созданной приложением. Двухмониторный smoke не воспроизводит исходную конфигурацию Issue #2.

**Вердикт: локальный release candidate. Публичный релиз заблокирован до успешной проверки штатного обновления в Windows Sandbox или отдельной VM.**
